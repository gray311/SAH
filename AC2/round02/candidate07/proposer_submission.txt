  edit_solution: 'Change the code inside the # EVOLVE-BLOCK region. Two accepted formats: (1) PREFERRED — one or more targeted SEARCH/REPLACE diff blocks, each matching the current program exactly: ""<<<<<<< SEARCH"" / exact original lines / ""======="" / new lines / "">>>>>>> REPLACE"". Do not rewrite the whole region for a small change. (2) A full rewrite — the complete new EVOLVE-BLOCK body as plain code (fenced ```python is allowed; the markers are optional). The fixed entry function and imports outside the block are preserved automatically. After editing, call evaluate_solution to score it.'
  evaluate_solution: Run the current program through the task evaluator and report its score. Returns combined_score (higher is better), validity, any error, your best score so far, and how many evaluations remain. Use the feedback to improve the code, then evaluate again. The best-scoring version is kept automatically. Your number of evaluations is limited.
  probe_solution: Cheaply score the CURRENT program on SUBSAMPLED data (~10s vs minutes). Fast (~10s per probe), separate budget (e.g., 30 probes available), NOT evaluated through full evaluation budget. Scores are approximate and NOT directly comparable to full evaluation scores — use this to rapidly rank multiple variants (e.g., 5-10 function representations, 20-50 parameterizations each), then confirm the top 3-5 candidates with evaluate_solution. Do not use probes instead of evaluate_solution for final verification; use probes to explore MORE candidates before committing eval budget.
  finish: End the session. Call this when your evaluation budget is exhausted or you cannot improve the best score further. The best-scoring program is submitted automatically.
