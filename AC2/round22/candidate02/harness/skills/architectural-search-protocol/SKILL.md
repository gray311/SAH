# C2 Maximizer: Architectural Search Protocol\n\n## Core Principle\n600-interval step functions are over-parameterized. Effective changes are STRUCTURAL: vary interval count (200-1200), reshape height distributions, change symmetry. DIVERSIFY architecture first.\n\n## Phase 1: Architecture Diversification (iterations 1-10)\n\n1. Call analyze_function_structure to get: interval count, height levels, symmetry\n\n2. Generate 4-5 ARCHITECTURAL variants:\n   - A: Downsample to 200-250 intervals\n   - B: Upsample to 800-1000 intervals with smoothing\n   - C: Multi-level (4-5 heights, asymmetric)\n   - D: Narrow peak (30% support, height 2.0-2.5)\n   - E: Asymmetric (left!=right peak heights)\n\n3. Probe all 4-5, evaluate best\n\n4. If no improvement: try next architectural pattern\n\n## Phase 2: Spectral Refinement (iterations 11-20)\n\n1. Analyze function structure again\n2. Generate 3 spectral variants:\n   - High-frequency boost (fine-scale oscillations)\n   - Low-frequency smoothing (increase intervals, interpolate)\n   - Mass redistribution (center vs edges)\n\n3. Probe, evaluate best\n\n## Phase 3: Extreme Diversification (iterations 21-30)\n\n1. Try: 150-interval coarse, asymmetric multi-peak, Gaussian-like\n2. Probe 3, evaluate best, submit\n\n## Key Rules\n- DIVERSIFY: don't stay in one architectural regime\n- Avoid 600-interval - try 200, 800, 1200\n- Structural insights > parameter tweaks\n- Probes are cheap: 4-5 probes before each full eval
