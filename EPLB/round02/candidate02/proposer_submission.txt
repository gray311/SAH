  # MoE EPLB Optimization Strategy
  
  ## Understanding the Task
  
  The EPLB algorithm rearranges experts across physical GPUs to balance load. Key metrics:
  - **Load balance**: How evenly utilization is distributed (lower variance = better)
  - **Efficiency**: Algorithm runtime (faster is better)
  - **Combined score**: Higher = better balance, lower = better efficiency
  
  ## Using analyze_load_balance
  
  **CRITICAL**: Call analyze_load_balance AFTER each edit to quickly assess your changes.
  
  - It gives you a fast approximation of load balance quality (~10ms vs seconds for full eval)
  - Does NOT consume your evaluation budget
  - Use it to iterate through many ideas before committing to full evaluation
  
  ## Expert Replication Strategies
  
  1. **No replication**: Baseline - fastest but potentially unbalanced
  2. **Uniform replication**: Copy all experts equally - simple but may not be optimal
  3. **Weighted replication**: Replicate experts based on their utilization weights
  4. **Hierarchical replication**: Organize into groups first, then replicate within groups
  
  ## Optimization Loop
  
  1. Start with analyze_load_balance on seed to establish baseline
  2. Edit to try a new replication strategy
  3. Immediately call analyze_load_balance
  4. If improvement, try variations on that approach
  5. Once you find a consistently better approach, use evaluate_solution to confirm
  6. Repeat with more sophisticated strategies
  
  ## Common Patterns
  
  - **Try small changes first**: Modify one function at a time (e.g., just balanced_packing)
  - **Test different groupings**: The num_groups parameter affects the hierarchy
  - **Consider num_physical_experts**: How many replicas to create matters
  - **Beware of complexity**: More complex = slower runtime, which hurts combined_score
  
  ## Decision Tree
  
  If analyze_load_balance shows NO improvement after an edit:
  - The edit broke something OR the direction is wrong
  - Either revert or try a fundamentally different approach
  
  If analyze_load_balance shows IMPROVEMENT:
  - This is promising! Test a few variations
  - Then confirm with evaluate_solution
  
  ## Final Check
  
  Before calling evaluate_solution, ask: "Will my changes actually improve the combined_score?"
  Remember: Better balance alone isn't enough - efficiency matters too.
