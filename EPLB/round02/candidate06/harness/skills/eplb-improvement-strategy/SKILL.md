# EPLB Improvement Playbook\n\n## Task\nImprove the rebalance_experts function to achieve better load balancing AND faster execution.\n\n## Strategy\n1. **Analyze current approach**: Read the seed algorithm, understand packing and replication logic\n2. **Choose direction**: Packing, replication, hierarchy, or performance optimization\n3. **Bounded search**: Implement 3-5 variants internally, pick best\n4. **Probe first**: Use probe_solution to rank variants cheaply\n5. **Evaluate best**: Call evaluate_solution on top candidate\n\n## Common Pitfalls\n- Don't break API: preserve input/output shapes exactly\n- Don't exceed time limits: keep internal search bounded\n- Don't ignore validity: combined_score = 0 on invalid programs\n- Probe is NOT full evaluation: use for ranking, not final scoring\n\n## Improvement Ideas to Try\n- Greedy bin packing with different tie-breaking\n- Power-of-two replication\n- Vectorized torch operations\n- Pre-computation caching\n- Topology-aware grouping (NVLink optimization)\n\n## Remember\n- The evaluator checks BOTH quality AND speed\n- Use time.perf_counter() to monitor internal execution\n- Combine_score rewards both objectives"
