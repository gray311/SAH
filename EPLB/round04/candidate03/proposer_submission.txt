      # Vectorized Packing Optimization Playbook
      
      ## Core Insight
      The balanced_packing function uses O(num_groups x num_packs^2) complexity due to Python loops. Vectorization reduces this to O(num_layers x num_groups x log(num_groups)).
      
      ## Transformation Steps
      
      ### Step 1: Identify the Bottleneck
      Find these patterns:
      Code pattern 1: for group in indices:
      Code pattern 2: valid = [p for p in range(num_packs) if pack_items[p] < groups_per_pack]
      Code pattern 3: candidates = [(pack_items[p], pack_weights[p], p) for p in valid]
      This is O(num_groups x num_packs) iterations with O(num_packs) work each = O(n^2).
      
      ### Step 2: Vectorized Solution
      Use batch sorting and arithmetic:
      sorted_indices = torch.argsort(-weight, dim=-1)
      pack_chunk = torch.div(sorted_indices, groups_per_pack, rounding_mode="floor")
      pack_index = pack_chunk * num_packs
      rank_in_pack = sorted_indices % groups_per_pack
      
      ### Step 3: Why This Works
      - torch.argsort(-weight, dim=-1): sorts groups by weight descending across all groups in one operation
      - torch.div(..., rounding_mode="floor"): computes which chunk each sorted group belongs to
      - pack_index = chunk * num_packs: assigns pack IDs
      - rank_in_pack = sorted_indices % groups_per_pack: rank within pack
      
      ### Step 4: Verification
      Expected properties:
      - Each pack has exactly groups_per_pack groups
      - Total load is balanced
      
      ### Step 5: Testing
      - Use probe_solution to test the vectorized version before full evaluation
      - Compare execution time (vectorized should be 10-100x faster)
      - Check load balance score
      
      ## Common Pitfalls
      - Don't mix vectorized and loop operations
      - Don't use Python's min() over a list
      - Ensure all tensors are on the same device
      - Use rounding_mode="floor" in torch.div for Python 3.9+ compatibility
