  body: |
    # EPLB Vectorization Guide
    
    ## The Problem: O(n*m) Python Loop
    The original balanced_packing() uses:
    - for group in indices: loop over num_groups
    - for p in valid: inner loop over num_packs
    - List comprehensions: [p for p in range(num_packs)]
    - min() with lambda key
    
    This is O(num_groups * num_packs) = O(n*m).
    
    ## The Solution: O(n log n) Vectorization
    
    ### Step 1: Sort All Groups at Once
    sorted_indices = torch.argsort(-weight, dim=-1)
    
    ### Step 2: Bulk Pack Assignment
    pack_index = sorted_indices // groups_per_pack
    rank_in_pack = sorted_indices % groups_per_pack
    
    ### Step 3: Compute Pack Weights Efficiently
    Use torch.bincount-style or scatter_add:
    ```python
    flat_pack_idx = pack_index.flatten()
    flat_weight = weight.flatten()
    pack_weights = torch.bincount(flat_pack_idx, weights=flat_weight, minlength=num_packs)
    ```
    
    ### Step 4: Pre-allocate, Don't Append
    OLD: pack_items = [0] * num_packs then append
    NEW: All tensors pre-allocated before the operation
    
    ## Complete Pattern Template
    
    ```python
    sorted_indices = torch.argsort(-weight, dim=-1, device=weight.device)
    pack_index = sorted_indices // groups_per_pack
    rank_in_pack = sorted_indices % groups_per_pack
    return pack_index, rank_in_pack
    ```
    
    This is O(n log n) due to the single sort, with O(1) packing assignment.
