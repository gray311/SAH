# Architecture-First Search for Erdos C5\n\n## Core Principle\nThe seed program uses random pattern generation, but we need to SYSTEMATICALLY explore step function ARCHITECTURES (number of steps, step locations, step values).\n\n## Step-by-Step Workflow\n\n1. CALL construct_step_function with num_steps=1 (bipartite)\n   - Step locations: [0, 0.5, 2] or similar\n   - This gives the simplest possible function\n\n2. CALL construct_step_function with num_steps=3, 5, 7, 10\n   - Try different numbers of steps systematically\n   - Each time, try different step locations\n\n3. SCREEN with probe_solution\n   - Run probe on each architecture\n   - Keep those with c5_bound < 0.375\n\n4. EVALUATE top candidates\n   - Call evaluate_solution on best candidates\n   - If combined_score > 1.0, finish\n\n5. If stuck, try step_locations variations:\n   - Bipartite: [0, a, 2] for different a\n   - Tri-partite: [0, a, b, 2]\n   - Golomb-like: [0, 0.4, 0.8, 1.2, 1.6, 2]\n\n## Avoid Common Mistakes\n- Do NOT call evaluate_solution on c5_bound > 0.375\n- Do NOT skip trying different num_steps values\n- Do NOT rely on the seed's random patterns first\n- ALWAYS use construct_step_function to control architecture
